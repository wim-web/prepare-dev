# gotest プラグイン: 主張の書き方

対象は Go モジュール。証拠の種類は `test`。結果は実行したテストケースの範囲でのみ成り立つ（`scope.bounded = true`）。

## spec の native 参照

```yaml
native:
  - plugin: gotest
    ref: internal/runtime::[C1]
```

`ref` は `<パッケージのインポートパスの末尾一致>::<テスト名に含まれる文字列>`。テスト名は `go test -json` が出す名前で、サブテストは `TestX/名前`（空白は `_`）になる。`t.Run("[C1] ...", ...)` のように主張の印を付けると、一つの主張に複数のテストを対応づけられる。パッケージ部分を空にした `::[C1]` は、どのパッケージのテストにも一致する。`verify_run` の `targets` にテストファイルを渡すと、そのディレクトリのパッケージを実行する。`config.packages` でパッケージを直接指定することもできる。

## 入力の記録

`inputs.files` には、結果を左右するファイルを内容の sha256 とともに記録する。記録したファイルが変わるか消えると、その証拠は現在の版に当てはまらなくなる。

1. `go list -deps -test -json` が報告する、テストがビルドするパッケージのファイル（Go のソースのほか cgo・C・C++・アセンブリ・ヘッダー・syso と埋め込みのファイル）を記録する。テストファイルは実行するパッケージのものだけで、依存先のテストはビルドされないので含めない。
2. 対象はメインモジュール、ローカルのディレクトリへ `replace` したモジュール、`vendor/` のパッケージ。それ以外の外部モジュールは `go.sum` に一致することを前提にし、ファイルは記録しない。
3. 実行するパッケージの `testdata/` の下のファイルはすべて記録する。テストが読むファイルは `testdata/` に置くのが Go の決まりで、設定は要らない。
4. テストが実行中に `go build` や `go run` で作るプログラムは、`config.input_packages`（例: `["./cmd/tool"]`）に書く。そのパッケージと依存先のファイルを 1 と同じ規則で含める。
5. それ以外にテストが読むファイル（`testdata/` の外にある trace など）は、`config.impl_files` にルートからのパスかパターンで書く。パターンは `*`・`?`・`[...]` をパスの一段の中で、`**` を任意の段数のディレクトリに使える（例: `["model/**"]`）。`**` は `node_modules` と `.` で始まるディレクトリには入らず、`.` で始まるファイルはパターンに一致しない。一致するファイルがない書き方は誤りとして実行を止める。
6. `go.mod`、`go.sum`、`go.work`、`go.work.sum`、`vendor/modules.txt` を含める。

ファイルの追加も検出するために、`inputs.listings` にディレクトリごとのファイル名の一覧の sha256 を記録する。対象は、ファイルを記録したパッケージのディレクトリ（その段だけ）、埋め込んだディレクトリ（下まで）、`testdata/`（下まで）、`impl_files` のパターンが探すディレクトリ。そこにファイルが増えるか減ると、その証拠は現在の版に当てはまらなくなる。

## 実行

`go test -json -count=1` を実行し、イベントの記録を証拠として保存する。`-count=1` でテストのキャッシュを使わない。`config.env` で環境変数を渡せる。デーモン自身の環境にある `PREPARE_DEV_` で始まる変数はテストに渡さず、`config.env` に書いたものだけを渡す。

テストは、環境変数 `PREPARE_DEV_BOUNDS_DIR` が指すディレクトリ（その RUN の出力の中）に JSON のファイルを書くと、その数値と文字列を RUN の `scope.bounds` に残せる。流した件数や使ったデータ、検査したものを証拠に残すのに使う。プロジェクト共通の設定は `.prepare-dev/config.json` の `plugins.gotest` に置ける。

使った `go` の場所を `tool.extra.path` に残す。検証はデーモンが動かすので、道具の探し方（PATH と `~/.elan/bin`・`~/.cargo/bin`・`~/.local/bin`）と、`PREPARE_DEV_` で始まるもの以外の環境変数（`GOFLAGS`、`CGO_ENABLED` など）は、デーモンを起動した CLI のものが使われ続け、RUN には残らない。道具や環境を変えたら `prepare-dev stop` で止めてから使う。

## 結果の対応

| 状況 | claim の結果 |
| - | - |
| 対応するテストがすべて成功 | `verified` |
| 一つでも失敗、またはパッケージのビルドに失敗 | `failed` |
| 対応するテストがない、またはスキップだけ | `unknown` |
| タイムアウト | `timeout` |
| go が動かない、出力が得られない | `tool_error` |
