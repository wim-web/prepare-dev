```yaml
  - 同一rootの排他にはrootから決めたloopback TCPポートをOSの生存期間ロックとして使う。ポート競合時は起動を拒否して診断する。
new_decisions:
  - esbuildでCLIをbundleし、UI・skills・guidance・ライセンスをnpm tarballに含める。

coverage: {}
```

## 計画
UIは既存の質問・候補データを使い、固定のReact部品で説明、比較、候補、推奨理由、回答欄を表示する。MarkdownはReactとして描画し、HTML実行はしない。json-renderの入力・生成・endpoint・依存を同じ変更で削除する。過去のuiフィールドは読み込み互換のため許容する。

配布はnpm tarball。bin/prepare-dev.mjs、ui/index.html、skills/、guidance/、ライセンス、版とbuild識別子を含む。bundleはNode組み込みモジュール以外を同梱。実行位置から配布rootを求め、そこからUIと自身のCLIを解決する。開発中のsource実行も維持する。

initは共通runtime経由で記録を初期化し、skillsをコピーする。MCP設定を変更しない。利用者が変更した既存skillsは上書きせず、差異を報告する。CLIは--prompt-file/--options-fileで説明と候補を渡せる。

runtimeは起動時、root固有のloopback TCP leaseを確保してから永続状態を開く。HTTPは別の空きポートで配信し、leaseはプロセス終了でOSが解放する。CLIはroot・版・build・実行経路をHTTPで確認し、異なるruntimeには明示的な停止・再起動を案内する。停止はHTTPの応答先を検証して行う。停止受付と同時に新しい操作の受付を閉じ、body受信中の操作も保存前に停止状態を確認する。検証ジョブが動作中なら停止を拒否する。

## 実装順序
1. React画面と質問APIの移行。
2. インストール位置の解決、init・skillsコピー、daemonの起動と識別。
3. UI＋CLIのbuild/packと配布物テスト。
4. 別プロジェクトでUI回答、判断、仕様、実装、Vitest/Leanの検証、traceを実行。

## 前段との照合
DEC-0004のCLI中心・MCP任意、DEC-0005のjson-render不採用、DES-0002の判断画面を具体化する。tarballと依存選択は今回の実装指示の範囲で決めた技術的選択。旧案Gを再採用しない。SPEC-0001の確定・回復契約とSPEC-0003の入力追跡を維持する。未実装を検証済みとは扱わず、新しい受入仕様と実装をレビューする。

## 通信と更新
UIは接続エラー時にSSEを作り直し、接続成功時に一覧と選択中の質問を取得する。初回取得失敗、回答のclose/staleへの遷移にも表示を追従させる。開発用Vite proxyはfrontendと同一Originの要求だけbackend Originへ書き換える。CLIのrecord putは読んだexpected-revとexpected-sha256の明示を必須とする。
