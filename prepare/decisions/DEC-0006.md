## 判断（人の回答）

Q-0027 で「Go で作り直す」を選んだ（補足なし）。チャットでは「じゃあgoでいいです」と答え、判断画面について「go + react build でしょ？」と補足した。

## 読み取ったこと

- 本体（記録を管理するデーモン、CLI、検証プラグイン）を Go で書き直し、OS とアーキテクチャごとの実行ファイル一つで配る。使う人の環境に Node.js を求めない。
- 判断画面は React のまま作る。Vite で HTML ファイル 1 枚にビルドし、Go の実行ファイルに埋め込む。Node.js は画面のビルドとテストにだけ使う。
- 既存の記録・質問・検証結果（RUN）・ジャーナルの形式は変えない。

## 棄却した案

- Node.js のまま一つの実行ファイルにする: 書き直しは要らないが、本体を TypeScript にしておく理由がないまま残り、ファイルが 140MB を超える。
- 今のまま npm の tarball で配る: Node.js を使わないプロジェクトでも Node.js 26 以上が必要になる。

## 影響

- REQ-0010（Node.js 26 以上が前提）を改訂する。
- DES-0003（npm tarball の設計）は置き換え、Go 版の設計を新しく書く。
- SPEC-0001・SPEC-0003・SPEC-0004 の確認手段を Go のテストに付け替え、配布の条件を書き換える。
- DEC-0005（判断画面を React で作る）は引き続き有効。
