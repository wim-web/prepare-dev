## 受入範囲
REQ-0009 の判断画面と REQ-0010 の配布物を検査する。画面は既存の prompt/options を使い、背景・候補の帰結・推奨理由と比較表を読めることを確かめる。単一選択・複数選択・自由記述、送信中・完了・失敗・stale の表示は実ブラウザでも操作する。回答は判断画面からだけ受け付ける（A1）。

配布物の検査（P1〜P3）は、実行ファイルを別の場所に置き、PATH を `/usr/bin:/bin` にして（そこに Node.js・npm・pnpm・Go が無いことを確かめて）行う。init、skills のコピーと更新、同時起動、識別、停止、強制終了の後の再起動、シンボリックリンク経由の root、lease ファイルを消されたデーモンとジャーナルを置き換えられたデーモンの停止、マージしたジャーナルの扱い、TypeScript 版の残したデーモンの検出、質問・回答・判断・trace・bundle・ui、MCP の入口が無いことを確かめる。別プロジェクトで実際の Lean の実行も行い、証拠の対象版を確かめる。

主張の証拠（RUN）は、checkout からビルドした実行ファイルで動かすテストの結果である。Go のテストの検証実行は `.prepare-dev/config.json` の `plugins.gotest` を使い、テストが実行中にビルドする `./cmd/prepare-dev`（input_packages）と、読むファイル（`model/**`、`ui/**` を impl_files、各パッケージの testdata は自動）を入力に含める。e2e は検査した実行ファイル（checkout からのビルドか、その sha256）を RUN の `scope.bounds` に残し、デーモンの環境の `PREPARE_DEV_E2E_BINARY` は検証実行に渡らない。次は人が実行して確認記録 REC-0007 に残す（RUN ではない）: `PREPARE_DEV_E2E_BINARY` に配布物の tar.gz から取り出した実行ファイルを渡して動かす e2e、Linux のコンテナでの配布物の実行、TypeScript 版（342bc64）との共存と戻し方、ブラウザでの操作。

画面の表示（U1）は React の部品のテストを Vitest で確かめる（`ui/` を project_dir にする）。埋め込むビルドがそのソースから作られ、その後に書き換えられていないこと（B1）と、それ以外の主張は Go のテストで確かめる。

ブラウザでの確認は実操作の記録として残す。自動テストの RUN を、画面の全操作を検証した証拠とは扱わない。
