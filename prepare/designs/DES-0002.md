## 変更の範囲

判断用 UI は React で実装し、json-render を採用しない。AI が質問ごとに画面構成の JSON を生成する機能、json-render の catalog と spec、およびそれらの検証を必須要件から外す。既存の React、Vite、単一 HTML 配信、質問と回答の保存は維持する。

目的は、プロダクトの意図を整理し、人が内容を理解して判断し、仕様・実装・検証結果まで追えること。画面生成方式そのものは目的にしない。

## 判断画面の契約

- エージェントは質問の背景、何を決めるか、なぜ人の判断が必要か、候補とその帰結、推奨と理由を整理する。
- `prompt` の説明と、`options` の `label`、`summary`、`recommended`、`reason` を React の部品で表示する。説明は Markdown の段落・箇条書き・表を表示でき、比較が必要なときは表を使える。画面の配置は UI 側が管理する。
- 一つの質問は一つの独立した判断を扱う。複数の判断は別の質問にする。複数選択は一つの判断の中で複数候補を選ぶ場合に使う。
- 技術的な調査で決められる事項はエージェントが調べて処理する。人に尋ねるのは目的、優先順位、価値判断、許容するトレードオフ、調査では得られない事実。
- CLI から質問の内容を登録し、ブラウザ UI で回答し、その回答を runtime から取得・判断として適用できる。DEC-0004 の CLI 配布の方針と、MCP の入口を提供しない DEC-0007 に従う。
- 回答と対象の版の対応、一度だけの適用、中断後の再取得、検証プラグインの契約は変更しない。

## 廃止する契約と実装との差

新しい質問作成 API は画面レイアウト用の `ui` を受け取らず、`ui.spec` を正本に含めない。CLI に画面 JSON を渡す機能は追加しない。旧 `GET /api/questions/:id/ui` の json-render spec 生成契約も廃止し、UI は質問データから描画する。

移行時は CLI・MCP・HTTP の入力、UI の呼び出し、runtime の生成処理、依存パッケージを同じ変更で更新する。過去の質問と回答は保持し、既存質問の `ui.spec` が残っていても新しい表示には使わない。過去の回答や判断を書き換えない。

この変更はDES-0003に基づき実装した。現行の受入範囲はSPEC-0004、実装・配布物の検証結果はREC-0006を参照する。

## 変更後の受入条件

1. 質問の背景、判断点、候補ごとの帰結、推奨理由を同じ画面で読み、仕様書の内部 ID を調べずに回答できる。
2. 比較が必要な質問では、説明に含まれる表を読める。画面レイアウトの JSON を作る必要がない。
3. CLI で質問を作成し、UI で回答し、回答を取得して判断として記録する流れが通る。
4. json-render の依存・画面生成・catalog 検証を要求せずに、1〜3 を満たす。既存の版照合、二重適用防止、再取得の検証も通る。
