## 要求
prepare-dev を OS とアーキテクチャごとの実行ファイル一つで配り、使う人の環境に Node.js などの言語処理系を求めない。検証器（Lean・Vitest・Go など）は、検証する環境に利用者が用意する。エージェントは skills の手順に従って CLI を使う。質問への回答は人が判断画面で行うもので（回答が判断になる手順は REQ-0001）、エージェントが使う CLI には回答の操作を置かず、回答は判断画面からの要求だけを受け付ける。同じ利用者のほかのプロセスが判断画面を装うことまでは防がない。MCP の入口は提供しない（DEC-0007）。

## 用語
- 対象プロジェクト（root）: prepare-dev が記録を置くディレクトリ。パスの書き方が違っても、同じディレクトリなら同じ対象プロジェクト。
- 実行ファイル: OS とアーキテクチャごとの `prepare-dev`。配布物は、それを含む tar.gz。
- build: 実行ファイルの内容。内容が同じなら、置き場所が違っても同じ build。
- 記録を書くもの: 対象プロジェクトの記録・質問・検証の結果（RUN）を書き換えるもの。
- skills の配置先: 対象プロジェクトの `.agents/skills` と `.claude/skills`。利用者は別の場所を指定するか、コピーしないことを選べる。
- 利用者の設定: 対象プロジェクトに既にある prepare-dev の設定（`.prepare-dev/config.json`）と、エージェントの設定ファイル（MCP の設定など）。

## 受入条件
- P1: 別の場所に置いた実行ファイルだけで help・version、init、status、ui、record、q、trace、bundle、verify が動く。元の checkout を参照せず、Node.js と Go が PATH に無くても動く。verify は、検証器が環境にあるプラグイン（受入では Lean）で確かめる。
- P2: init は skills を配置先にコピーし、MCP の設定を書かず、利用者の設定を変えない。同じ内容なら何も変えない。利用者が編集した skill は上書きせずに差異を報告し、利用者が求めたときだけ退避してから置き換える。prepare-dev が入れて編集されていない skill は、新しい版で更新できる。
- P3: 一つの対象プロジェクトに記録を書くものは同時に一つだけ。利用者が手で何かを起動しなくても操作できる。異なる build が黙って記録を書くことはなく、そのときは動いているものと止め方を示す。記録を書くものが異常終了しても、利用者が手で後片付けをせずに次の操作を続けられる。
- P4: 独立したプロジェクトで、要求作成→質問→判断画面で回答→DEC→SPEC→実装→実際の検証器での RUN→trace を通す。パッケージ管理サービスへの公開は対象外。
- P5: 質問への回答は判断画面からだけ受け付け、CLI に回答の操作は無い。MCP の入口も無い。

旧 REQ-0002〜0008（配布と起動の要求。いずれも superseded）の、機械固有のパスを書かない、配布物だけで動く、UI を同梱する、という意図を引き継ぐ。DIS-0001 の案 G（skills を利用者単位の置き場に置き、MCP の登録を軸に段階を分ける案）は採用しない。

## 観点の対応
- users・rationale: 別プロジェクトで prepare-dev を使う利用者と、CLI を呼ぶエージェントのための要求。DEC-0004・DEC-0006・DEC-0007 に基づく。
- scenarios_normal: 実行ファイルを置いて init すると、skills と記録の操作を使える。質問・回答・判断・検証を同じ対象プロジェクトに記録し、trace で追う。
- scenarios_exception: 同時に操作しても、記録を書くものは一つのまま。異なる build のものが動いていれば書かずに止め方を示す。異常終了の後も次の操作で続けられる。利用者が編集した skill は上書きせずに報告する。検証の実行中は停止を拒否する。
- terms・data: 上の用語のとおり。配布方式を変えても、過去の質問・判断・RUN のファイルを書き換えない（読み直しても内容が変わらない）。
- states・rules: 記録を書くものが無い、動いている、異なる build のものが動いている、異常終了の残りがある、を区別する。記録を書くものを一つにし、利用者の設定と skill の編集を守る。
- quality・constraints: checkout・Node.js・Go に依存しない。macOS と Linux（arm64・amd64）、loopback 接続、一人の利用者のホストが前提で、Windows は対象外。記録を書く作業コピーは一つ。ブランチや worktree で並行して書いた prepare/ をマージしたときの衝突は、マージのときに直す（DEC-0008）。直した結果に矛盾があれば、書き込まずにそれを示す。判断画面を直す開発者だけが Node.js を使う。検証器は利用者が用意する。prepare-dev 自体の開発者が配布物を作らずにソースから動かせることは保つ（開発の手順で確かめ、受入条件にはしない）。
- priority・acceptance: must。SPEC-0004 の P1〜P3、A1（P5）、B1・D1 と、配布物による一連の利用の確認記録（P4）で確認する。

coverage の decided は観点の扱いが決まっている意味であり、全ホスト・全 OS での確認済みの意味ではない。実行環境と確認した範囲は確認記録 docs/2026-11-09-go-verification.md に残す。
