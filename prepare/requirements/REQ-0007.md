## 現行要求への置き換え（2026-11-09）

DEC-0004と、UI・CLI配布まで実装・検証する指示に基づき、この旧案の要求を置き換えた。現行の要求はREQ-0010、設計はDES-0003、受入仕様はSPEC-0004。本記録の残りは変更前の案と検討理由を保存する履歴であり、現行実装への追加要件にはしない。

ソース直実行とソースを検査する開発経路はDES-0003のsource実行維持と配布検証記録に引き継ぐ。

## 要求

開発のループを壊さない。`pnpm cli` と `pnpm test`（vitest）は常にソースを見る。ビルドや束ねた物を作る案（C、D）を選んでも、入口側のソースの変更が `pnpm cli` に即時に反映され、テストが古いビルド成果物（C では `dist/`、D では束ねたファイル）を検査して通ることがない。`mcp.test.ts` と `scripts/e2e-crash.sh` は新しい起動経路でも通る。

デーモン側のソースの変更は、デーモンを止めて（`prepare-dev stop`）起動し直すまで反映されない。これは現状と同じで、本要求は変えない。

`coverage.self` は、この要求が案の選択に依存しないことを示す（decided）。用語は DIS-0001 の「用語」に従う。

## 根拠

- 所有者は開発で `pnpm cli` の即時実行を保ちたい（DIS-0001 §関係者）。
- `exports` を `dist/` に向けると、alias の無い vitest はテスト内の `@prepare-dev/*` も `dist/` に解決し、ソースを直しても古い `dist/` を検査して通る経路が生まれる（DIS-0001 §現状 テスト）。
- `mcp.test.ts` は tsx とソースの絶対パスで入口を起動する前提で書かれており、起動経路を変えると追従が要る（DIS-0001 §現状 デーモン起動）。
- デーモンは終了条件なく常駐し、入口は既存の `daemon.json` を見つければそれに接続する。ソース経路でデーモン側の変更を自動で検出するのは本件の範囲外（REQ-0004 対象外）。

## シナリオ

- 通常: Given 入口側（CLI、MCP）のソースを変更した、When `pnpm cli status` を実行する、Then ビルドなしで変更が反映される。
- 通常: Given デーモン側（runtime）のソースを変更した、When `pnpm cli stop` の後に `pnpm cli status` を実行する、Then 新しいデーモンが立ち、変更が反映される。
- 通常: Given ソースを変更した、When `pnpm test` を実行する、Then テストはソースを検査する。
- 例外: Given ビルド成果物が古い、When `pnpm test` を実行する、Then 結果はビルド成果物の内容に左右されない。
- 例外: Given 起動経路を変えた、When `mcp.test.ts` と `scripts/e2e-crash.sh` を実行する、Then 新しい経路で入口とデーモンが起動し、通る。
- 例外（中断と再試行）: Given ビルドが途中で止まった、When `pnpm cli` を実行する、Then ソース直実行なので影響を受けない。

## 受入条件

- AC-1: vitest の import が `src` に解決されることをテストで確認する（`exports` を変えた案でも）。
- AC-2: 入口側のソースを変更して `pnpm cli` を実行すると、ビルドなしで変更が反映される。デーモン側の変更は `stop` の後の起動で反映される。
- AC-3: `pnpm test` と `scripts/e2e-crash.sh` が新しい起動経路で通る。

## 対象外

- ビルドの速さ。
- 開発用の watch や hot reload。
- 常駐するデーモンがソースの変更を自動で検出すること。
