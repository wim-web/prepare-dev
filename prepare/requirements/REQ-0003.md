## 現行要求への置き換え（2026-11-09）

DEC-0004と、UI・CLI配布まで実装・検証する指示に基づき、この旧案の要求を置き換えた。現行の要求はREQ-0010、設計はDES-0003、受入仕様はSPEC-0004。本記録の残りは変更前の案と検討理由を保存する履歴であり、現行実装への追加要件にはしない。

配布物の位置とrootの解決、および一つの書き手という意図はREQ-0010/P1・P3へ引き継ぐ。全セッションに自動登録するMCPを前提とした対象一覧・対象外起動の案は採用しない。

## 要求

入口（CLI と MCP）は、自分がどの checkout または配布物から動いているかを自分で求め、対象リポジトリは `--root` が無ければ環境変数、次に cwd から決める。デーモンの起動も同じ経路で行い、道具リポジトリの位置を設定ファイルから受け取らない。

ホストが起動する `mcp` サブコマンドと、`--root` を明示しない CLI コマンドは、cwd に `.prepare-dev/config.json` が無ければ `prepare/` も `.prepare-dev/` も作らず、副作用なく終わる。`init` と `--root` を明示したコマンドはこの抑止の対象外（`init` は config.json を作るのが仕事）。

非対象の場所で起動された `mcp` は、終了してホストにエラーを返すか、ツールを公開せずに待つかのどちらかにする（Q-0003 で決める。作成予定）。終了すると G ではホストが毎セッション起動エラーを出す。待つとセッション数ぶん Node プロセスが常駐する（約 0.25 秒で起動、常駐の RSS は未計測）。

二つの入口（Claude Code と Codex、または MCP と CLI）が同時に起動してもデーモンは一つだけ立つ。

`coverage.self` は、この要求が H1（未検証）に依存することを示す。用語は DIS-0001 の「用語」に従う。

## 根拠

- 登録から絶対パスを外す（REQ-0002）には、入口側がそれ無しで root と自分の位置を決められる必要がある。`toolRepoRoot()` と `rootOf()` の既定順は既にあるので、変えるのは「ホストが渡す cwd と環境変数で足りるか」（H1）と「対象でないときの抑止」（H7）。
- 案 G では入口が機械上の全セッションで起動されるので、抑止が無いと無関係なプロジェクトに `prepare/` と `.prepare-dev/` ができる。`.prepare-dev/` は `ensureDaemon` が接続前に作るため、抑止は接続より前に要る（DIS-0001 §代替案 G、H7）。
- 現在の `ensureDaemon` と `serve` にはロックが無く、二つの入口が同時に `daemon.json` 不在を見ると両方が起動し、後勝ちで片方が孤児になる。G では入口が全セッションで起動されるのでこの競合は起きやすくなる。
- 対象が道具リポジトリ自身のときは、プロジェクト単位の登録（`pnpm cli mcp`）でその checkout のソースを動かす（H8。優先順位は未検証）。

## シナリオ

- 通常: Given ホストが対象リポジトリを cwd にして入口を起動した、When 入口が root を決める、Then `--root` なしで `.prepare-dev/daemon.json` を見つけ、同じデーモンに接続する。
- 通常: Given デーモンが無い、When 入口が起動する、Then 入口は自分の位置から求めた経路でデーモンを detached 起動し、既定の待ち時間（現在の `ensureDaemon` の値は 15 秒。要求ではなく現状値）内に接続する。
- 例外: Given `.prepare-dev/config.json` の無いディレクトリ、When `mcp` が起動した、Then 何も作らず、Q-0003 で決めた振る舞い（終了か待機）をする。
- 例外: Given 環境変数と cwd が違う場所を指す、When 入口が root を決める、Then 環境変数を優先する（現在の既定順を保つ）。
- 例外（同時起動）: Given デーモンが無く、二つの入口が同時に起動した、When 両方が起動を試みる、Then 一つだけがデーモンを立て、もう一方はそれに接続する。
- 例外（中断と再試行）: Given デーモンの起動が待ち時間内に終わらなかった、When 入口がエラーを返す、Then 原因が対象側の `.prepare-dev/daemon.log` に残り、再試行で二重起動しない。
- 例外: Given 対象＝道具リポジトリで worktree が複数ある、When プロジェクト単位の登録で入口が起動する、Then その checkout のソースが動く（H8）。

## 受入条件

- AC-1: 対象リポジトリを cwd にして `--root` なしで `prepare-dev mcp` を起動すると、`--root` 付きと同じデーモンに接続する。
- AC-2: `.prepare-dev/config.json` の無いディレクトリで `mcp` または `--root` なしの `status` を起動しても、`prepare/` と `.prepare-dev/` が作られない。`init` は従来どおり作る。
- AC-3: デーモンの起動に失敗したとき、原因が `.prepare-dev/daemon.log` に残り、再試行で二つ目のデーモンが立たない。
- AC-4: シェル起動の Claude Code、GUI 起動の Claude Code、Codex の三通りで、`args` に絶対パスの無い登録から接続できる（H1 の検証結果を DIS-0001 に記録）。
- AC-5: 対象＝道具リポジトリの worktree で、プロジェクト単位の登録によりその checkout のソースが動く（H8）。
- AC-6: デーモンが無い状態で二つの入口を同時に起動しても、デーモンは一つで、`daemon.json` はその一つを指し、孤児プロセスが残らない。

## 対象外

- ホストの cwd や環境変数の仕様そのもの。H1 が偽のホストには REQ-0002 の逃げ道（B、C、D）か B への切り替え（G）で対応する。
- 一つの対象リポジトリに対して意図的に複数のデーモンを動かすこと（SPEC-0001 の前提と同じ）。
