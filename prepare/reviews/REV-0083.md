## 言い直し

**この文書が提案していること**
prepare-dev の本体（記録を書くデーモン、CLI、検証プラグイン lean4・vitest・gotest）を Go で書き直し、配布は OS とアーキテクチャごとの実行ファイル一つにする。実行ファイルには、React の判断画面を 1 枚の HTML にビルドしたものと skills を埋め込む。MCP の入口は作らない。エージェントは skills の手順で CLI を使い、回答は判断画面からだけ受け付ける（DES-0004、DES-0002、REQ-0009・0010、SPEC-0004）。

今回の版では、工程の外の記録の規則を固めた。確認記録や引き継ぎの原文は REC、工程の外の案は PRO として runtime を通して書き、この規則を skills ですべての対象プロジェクトに求める（DEC-0013）。確認記録は、確かめた記録を自分の related_to から指し、一回ごとに新しく作り、checked に次を書く。

仕様は、手の確認ごとにやり直しの条件を書く。prepare-verify は、確認記録の checked.commit から今の作業コピーまでの変更がその条件に当たるかを報告する。dirty の確認記録は当たるものとして扱う。当たれば、コミットした後に確認をやり直すか、人に聞いて DEC にする。このリポジトリの条件は DES-0004 の表にある。

あわせて次を決めた。
- guidance を prepare-verify の references/ に置き、先頭に書いた版を `version --json` の plugins と比べる（DEC-0011）。
- CLI の status は、init を書き込まずに動かして、入れる・置き換える・残す・手で直す skills を示す。
- プラグインは Capabilities で設定の項目と型を宣言し、runtime は RUN の番号を取る前に誤りを止める（V5）。
- 主張の今の結果は、native のプラグインごとに最も新しい RUN で決める。当てはまらなければ古い RUN には戻らず、プラグインごとの結果のうち最も悪いものを取る（V6）。

**この文書によると既存の仕組みはどう動くか**
- CLI は root の daemon.json と /api/identity を見て、version と build が同じデーモンにだけ接続する。デーモンがいなければ、同じ実行ファイルを serve で起動して端末から切り離す。違う build なら止め方を示して終える。
- デーモンは .prepare-dev/lease の flock で、root ごとに唯一の書き手になる。記録・質問・RUN・ジャーナルは TypeScript 版と同じ形式で書く。操作の前に lease とジャーナルを確かめ、マージしたジャーナルの矛盾や回復できない取引があれば「Nothing is written until …」で書き込みを拒む。
- init は skills をコピーして digest を skills.json に残し、次の init では編集されていない skill だけを置き換える。
- 検証はデーモンが非同期に動かす。RUN は、記録した入力とディレクトリの一覧、主張の SPEC と REQ の版、プラグインの版が今と同じ間だけ「現在の版に当てはまる」。trace は links を両方向にたどり、主張ごとの current と missing を示す。
- DIS-0001 は TypeScript 版の時点の配布の問題の整理で、REQ-0010 に置き換わった。DES-0003 は npm tarball の旧設計で、DES-0004 に置き換わった。

言い直せない節は無く、Blocker は無い。前回（REV-0079〜0082）の指摘の処理は、記録とコードで確かめた。V6 の実装とテスト、CLI の status の skills、`version --json` の plugins、checked の形、手順 6 の差分の起点と終点、やり直しの条件の表は、どれも記録のとおりになっている。残った問題は次の Nit だけ。
