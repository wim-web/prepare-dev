## 言い直し

**この文書が提案していること。** SPEC-0002 は、DES-0001 rev 3 の設計（案 G＝利用者単位の MCP 登録、段階 1）に沿って、REQ-0002〜REQ-0007 の受入条件 27 件のうち 18 件を、vitest で機械的に確かめられる 22 個の主張 C1〜C22 に書き換える。各主張はテスト名に含めた印 `[Cn]` で vitest プラグインがテストと対応づけ、テストファイル 7 個の新設と `mcp.test.ts` への追記を `prepare-verify` に委ねる。残り 9 件の受入条件と REQ-0008 は理由付きで対象外にし、未回答の質問 Q-0002〜Q-0009 は推奨案を前提にして、回答で前提が覆ったときに各主張をどう改訂するかを §4 に書く。設計に無い新しい対応付けは C22 を REQ-0003 に結びつけた一点だけだと明示している。

**この文書によると既存の仕組みはどう動くか。** 入口は root を `--root` → `PREPARE_DEV_ROOT` → cwd の順で求め、`--root` の無い呼び出しでは「`config.json` がある」かつ「利用者単位の `targets.json` に実パスがある」の二条件で対象かを判定する。対象ならデーモンに接続し（無ければ `entryCommand()` で `serve` を起動して最大 15 秒 `daemon.json` を待つ）、非対象なら `mcp` はツールを一つも持たない MCP サーバとして待ち、CLI は終了コード 2 で何も作らない。`serve` は `Runtime.open` の前に `daemon.lock` を排他作成（claim）し、`listen` して `daemon.json` を書いたら lock を消す。死んだ保持者の lock は `rename` に成功した一つのプロセスだけが引き取る。`init` は `config.json`・`.prepare-dev/.gitignore`・`prepare/` を作って `targets.json` に登録し `setup_commands` を出力、`--migrate` で旧 `init` の痕跡を消す。`skills --user` は `~/.agents/skills` と `~/.claude/skills` に skill 単位の symlink を張る。デーモンは `daemon.json` と `/api/status` に `tool.root` と `ui: {path, found}` を出し、UI HTML が無ければ簡易フォームを返す。補足: 上の「仕組み」は現在のコードではなく DES-0001 の設計である。リポジトリの現状とは違うが、仕様本文はその区別を書いていない。
