## 言い直し

**この文書が提案していること**
REQ-0002〜0008 は、DIS-0001「prepare-dev の配布と起動」から導いた七つの要求である。段階 1（登録の可搬化）として、`init` が対象リポジトリに絶対パスを書かず既存登録を移行できること（REQ-0002）、入口が設定ファイル無しに自分の checkout と対象リポジトリを決め、`.prepare-dev/config.json` の無い場所では何も作らないこと（REQ-0003）、入口とデーモンが checkout（C/D では版と経路も）を報告し接続時に不一致を検出すること（REQ-0004）、skills が `init` 後に解決でき切れたリンクや古いコピーを検出すること（REQ-0005）、デーモンが UI を自分の checkout か配布物から見つけ、無ければ簡易フォームに落ちたことを出すこと（REQ-0006）、`pnpm cli` と `pnpm test` が常にソースを見ること（REQ-0007）を要求する。段階 2 を選んだ場合だけ、配布物のみで動くこと（REQ-0008、could）を加える。案と skills の置き方は Q-0002 で人が決め、要求の一部は案ごとに条件付きになっている。

**この文書によると既存の仕組みはどう動くか**
現在は `pnpm cli`（tsx でソース直実行）で動き、`init` は tsx と入口ソースの絶対パス、対象リポジトリの絶対パス（`--root`）を `.mcp.json` と `.codex/config.toml` に書き、`skills/*` を `.agents/skills/` に絶対 symlink する。既にファイルやブロックがあれば書かない。入口は `rootOf()` で `--root` → `PREPARE_DEV_ROOT` → cwd の順に対象を決め、`toolRepoRoot()` で自分の checkout を求める。デーモンが無ければ `ensureDaemon` が対象の `.prepare-dev/` と `daemon.log` を作ってから tsx でソースを detached 起動し、`daemon.json` で発見する。版や経路を報告する仕組みは無く、UI は道具リポジトリの `packages/ui/dist/index.html` を読み、無ければ黙って簡易フォームになる。vitest は alias 無しで `src/**/*.test.ts` を実行する。
