prepare-dev の本体（記録を書くデーモン、CLI、検証プラグイン）を Go で書き直し、OS とアーキテクチャごとの実行ファイル一つで配る（DES-0004）。この実行ファイルには、React の判断画面を Vite で HTML 1 枚にしたものと skills を埋め込み、MCP の入口は持たない。これは DES-0003 の npm tarball 案を置き換えるもので、DES-0002 の画面の契約は変えない。今回の版では次の二つを行う。一つ目に、検証プラグインの書き方（guidance）を `prepare-dev guidance` コマンドから prepare-verify skill の `references/` に移し、init が skills と一緒に配る。二つ目に、このリポジトリ自身の確認記録・引き継ぎ・具体化案を docs/ から REC-0001〜0007・PRO-0001 に移し、各記録の docs/ へのパスを記録の ID と links に置き換える。SPEC-0003 は、RUN が今の版の証拠になる条件（入力ファイル、ディレクトリの一覧、プラグインの版、テストの外の失敗）を定める。SPEC-0004 は判断画面と配布物の受入（U1〜P3）を定め、配布物の tar.gz・Linux・TypeScript 版との共存・ブラウザ操作は人が確かめて REC-0007 に残すとする。

**この文書によると既存の仕組みはどう動くか**
- **デーモンと記録の書き手**: CLI は root の daemon.json と `/api/identity` を使って、動いているデーモンの version と build を自分のものと比べる。デーモンが無ければ、同じ実行ファイルを `serve` で切り離して起動する。`.prepare-dev/lease` の flock を持つ、root ごとに一つのデーモンだけが、記録・質問・RUN・ジャーナルを書く。
- **skills の更新**: init は skills を `.agents/skills` と `.claude/skills` にコピーし、skill ごとの digest を `.prepare-dev/skills.json` に残す。次の init では、未編集の skill だけを新しい版に置き換え、編集された skill は conflicts として残す。
- **証拠の当てはまり**: 検証はデーモンがプラグインで実行する。RUN には、入力ファイルの sha256、ディレクトリの一覧、主張の SPEC と REQ の rev と sha256、プラグインの版が記録される。どれかが今と違えば、その RUN は現在の版に当てはまらない。
- **回答と確認記録**: 回答は判断画面（同じ Origin のブラウザの要求）からだけ受け付ける。確認記録（REC）は人が確かめたことの記録で、RUN の代わりにはならず、主張の結果も変えない。
