## 言い直し

### この文書が提案していること
DES-0004 は、prepare-dev の本体（デーモン、CLI、検証プラグイン）を Go で書き直す提案である。React の判断画面のビルド結果と skills を埋め込んだ実行ファイルを、OS とアーキテクチャごとに一つずつ配る。対象プロジェクトごとに一つのデーモンが、`.prepare-dev/lease` の flock で唯一の書き手になる。CLI は version と build が同じデーモンにだけ接続し、MCP の入口と CLI からの回答は持たない。
今回の版の変更は次のとおり。
- 検証プラグインごとの主張の書き方を prepare-verify の skill の references/ に置き、init で配る（DEC-0011）。
- status が、次の init が skills にすること（入れる・置き換える・残す）を示す。
- プラグインが設定の項目と型を宣言し、runtime が実行の前に誤りを止める（SPEC-0003 V5）。プラグインの版を上げ、前の RUN を当てはまらなくする。
- 主張の今の結果を、当てはまる RUN のうち最も新しいものにする（V6）。
- 工程の外で残すものを REC・PRO として runtime を通して書く規則を、skills ですべての対象プロジェクトに求める（DEC-0013）。確認記録の checked には commit（変更のある作業コピーなら base_commit と dirty）を書く。このリポジトリでは、変えた場所に応じて手の確認をやり直す。

DES-0002（React の判断画面、json-render の不採用）は今も有効である。DES-0003（npm の tarball）と DIS-0001（TypeScript 版の時点の配布の問題）は、置き換えられた当時の記録として残る。

### この文書によると既存の仕組みはどう動くか
- CLI は root の daemon.json を読み、`/api/identity` で、動いているデーモンの version と build を自分のものと比べる。デーモンが無ければ、同じ実行ファイルの serve を端末から切り離して起動する。
- デーモンは lease を取ってから記録を開き、127.0.0.1 の HTTP で API・判断画面・SSE を配る。記録・質問・RUN・ジャーナルはデーモンだけが書く。ジャーナルの矛盾や置き換わりを見つけたら、何も書かずに止まる。
- 検証はデーモンが非同期に走らせる。プラグイン（lean4・vitest・gotest）が、入力のファイルとディレクトリの一覧を記録する。runtime は、入力・一覧・主張の版・プラグインの版が今と一致する RUN だけを、今の版に当てはまるとする。trace は、要求から主張と RUN までをつなぐ。
- init は skills を digest つきでコピーする（skills.json）。記録の形式は TypeScript 版から変えない。
