## レビュー役の指摘

1. **major** abort 後の清掃途中は inflight=false だが、C3 のファイル整合性を満たさない。モデルはこの回復途中の状態を含めていない
   - 対象: prepare/specs/SPEC-0001.md:102-120; model/PrepareDev/Spec/Step.lean:45-51,131-137; packages/runtime/src/questions.ts:426-449
   - 根拠: 仕様は任意の非 inflight 状態に整合性を要求するが、実装は abort 追記と仮更新撤回を別々に永続化し、モデルは recover を一遷移で扱う。障害時の保証範囲とモデル粒度の不一致。主担当が abort 直後に障害を注入して再現し、次の起動では清掃されることも確認した。回復不能という指摘ではない。

2. **major** C2 と C3 の native 参照が、それぞれの主張を構成する全命題を含まない
   - 対象: prepare/specs/SPEC-0001.md:22-37,116-117; model/PrepareDev/Spec/Theorems.lean:82,99,194,297; plugins/lean4/src/index.ts:203-241
   - 根拠: commit 時点の現在版一致を扱う step_commit_guard と、回答の保存継続を扱う answers_monotone は存在する。しかし指定された committed_matches_snapshot と quiescent_consistent の命題にはその全体が含まれず、RUN の命題・公理監査から主張全体を追えない。仕様と保証の対応を明示する必要がある。

3. **major** 入力一式の版を特定する契約に対し、vitest の依存収集と現在版への適用可否判定が不足している
   - 対象: docs/2026-11-08-concretization-proposal.md:316-318; plugins/vitest/src/index.ts:128-158; packages/runtime/src/runs.ts:256-289
   - 根拠: 依存 lockfile と package.json を収集せず、追加 impl_files の import 先もたどらない。runtime は記録済み入力のみを比較するため、未収集依存が変わっても検出できない。主担当の一時プロジェクトで lockfile と追加実装の依存を変更しても入力集合・ハッシュが同一になることを再現した。
