## 言い直し

**この文書が提案していること**
prepare-dev の本体（記録を書くデーモン、CLI、検証プラグイン lean4・vitest・gotest）を Go で書き直し、React の判断画面のビルドと skills を埋め込んだ、OS とアーキテクチャごとの実行ファイル一つで配る。MCP の入口は持たない。エージェントは skills に従って CLI を使い、回答は判断画面からだけ受け付ける。
今回の版では、工程の外の記録（REC・PRO）の決まりを二つに分けた。一つは skills を通してすべての対象プロジェクトに入る規則で、内容は次のとおり。工程の記録を runtime の外に書かない。書き込みが止まっている間は人への報告に書く。確認記録から、確かめた記録を指す。checked に commit と sha256 を書く。checked の commit からの差分を報告する。もう一つは、このリポジトリで手の確認をやり直す条件の表である。
あわせて次を決める。プラグインは設定の項目と型を宣言し、runtime は RUN の番号を取る前に、知らない項目・型の違い・知らないプラグイン名を止める（V5。プラグインの版を上げて前の RUN を外す）。主張の今の結果は、当てはまる RUN のうち最も新しいものにする（V6）。guidance は版の見出しを付けて prepare-verify の references/ に置く。status は init を書き込まずに動かし、skills について次の init がすること（入れる、置き換える、残す）を示す。

**この文書によると既存の仕組みはどう動くか**
CLI は root の daemon.json にある URL の /api/identity に問い合わせ、version と build を自分と比べる。同じならそのデーモンに接続し、デーモンがいなければ同じ実行ファイルを serve で端末から切り離して起動する。
デーモンは .prepare-dev/lease の flock で唯一の書き手になり、記録・質問・RUN・ジャーナルを TypeScript 版と同じ形式で書く。操作の前に lease とジャーナルを確かめ、マージ後の矛盾や回復できない取引があれば「Nothing is written until …」の誤りで書き込みを拒む。
init は skills をコピーして digest を skills.json に残し、次の init では編集されていない skill だけを置き換える。RUN は、入力・ディレクトリの一覧・主張の記録の版・プラグインの版が今と一致する間だけ、現在の版の証拠になる。trace は links を両方向にたどるので、確認記録も引ける。
