## 言い直し

**この文書が提案していること**
prepare-dev の本体（記録を書くデーモン、CLI、検証プラグイン）を Go で書き直す。React の判断画面を 1 枚の HTML にしたものと skills を埋め込み、OS とアーキテクチャごとの実行ファイル一つで配る。MCP の入口は無く、エージェントは skills の手順で CLI を使い、回答は人が判断画面からだけ行う（DES-0004、DES-0002、REQ-0009・0010、SPEC-0004）。

今回の版では、工程の外の記録（確認記録と引き継ぎの原文は REC、工程の外の案は PRO）の決まりを二つに分けた。
- skills ですべての対象プロジェクトに入る規則: 確認記録は確かめた記録を自分の related_to から指し、一回ごとに新しく作る。checked には commit を書き、変更のある作業コピーから作ったものなら base_commit と dirty を書く。確認記録は関門にせず、報告で「checked の commit から HEAD までの差分が確認の対象に触れるか」を示す。
- このリポジトリの表: 変えた場所ごとに、やり直す手の確認を挙げる。

あわせて次を決めた。
- status は init を書き込まずに動かし、次の init が入れる・置き換える・残す skills を示す。
- プラグインは設定の項目と型を宣言する。知らない項目、型の違い、知らないプラグイン名は RUN の番号を取る前に止める。宣言の無いプラグインは何も受け付けず、版を上げて V5 より前の RUN を当てはまらなくする（SPEC-0003 V5）。
- 主張の今の結果は、当てはまる RUN のうち最も新しいものにする（V6）。

**この文書によると既存の仕組みはどう動くか**
CLI は root の daemon.json と /api/identity を見て、version と build が同じデーモンにだけ接続する。いなければ同じ実行ファイルを serve で切り離して起動する。

デーモンは .prepare-dev/lease の flock で唯一の書き手になり、記録・質問・RUN・ジャーナルを TypeScript 版と同じ形式で書く。操作の前に lease とジャーナルを確かめる。マージ後の矛盾や回復できない適用があれば、「Nothing is written until …」の誤りで書き込みを拒む。

init は skills をコピーして digest を skills.json に残し、次の init では編集されていない skill だけを置き換える。検証はデーモンが lean4・vitest・gotest で動かす。RUN は、記録した入力・ディレクトリの一覧・主張の SPEC と REQ の版・プラグインの版が今と同じ間だけ証拠になり、trace は links を両方向にたどる。

DIS-0001 は TypeScript 版の時点の配布の問題の整理で、REQ-0010 に置き換わった。DES-0003 は npm tarball の旧設計で、DES-0004 に置き換わった。

言い直せない節は無く、Blocker は無い。
