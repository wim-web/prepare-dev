## 言い直し

**この文書が提案していること**
DIS-0001 は「どの機械・どの対象リポジトリでも同じ書き方の設定で prepare-dev を起動できる」ようにするための問題整理（discovery）であり、実装の決定ではない。根本原因を「`init` が機械固有の絶対パス四つを対象リポジトリに書き、ホストと入口がそれに依存している」ことと特定し、解く範囲を「段階 1: 登録の可搬化」と「段階 2: 道具リポジトリの checkout と node_modules なしで動く配布」に分ける。案は A（作らない）、G（利用者単位登録）、B（起動シム）、C（`tsc -b`）、D（esbuild）、E（棄却）、F（後回し）で、推奨は段階 1 なら G（不可なら B）、段階 2 なら D、C は推奨しない。どの案でも先に H1 を検証し、この工程の終わりに人へ一つの質問を出して三つの判断（a: 範囲の段階、b: skills の置き方、c: PATH 依存の受容）を仰ぐ。

**この文書によると既存の仕組みはどう動くか**
現在は道具リポジトリで `pnpm cli`（tsx でソース直実行）を使い、6 package の `exports` は `./src/index.ts` を指すため、`tsc -b` の出力は node 単体では動かない。`init` は `.prepare-dev/config.json` と `prepare/` を作り、`.mcp.json` と `.codex/config.toml` に絶対パスを書き（既存があれば書かない）、skills を `.agents/skills/` に絶対 symlink、`.claude/skills` を相対 symlink で置く。入口は root を `--root` → `PREPARE_DEV_ROOT` → cwd の順で決め、`.prepare-dev/daemon.json` でデーモンを見つけ、無ければ tsx＋ソースの絶対パスで detached 起動する。デーモンは `packages/ui/dist/index.html` をリクエストごとに読んで配信し、無ければ簡易フォームに落ちる。版・経路・checkout を報告する仕組みはない。

**2.** Major — DIS-0001 §仮説 H7

**3.** Major — DIS-0001 §問題 > 質問 1、§費用と期間、§成功

**6.** Nit — DIS-0001 §現状 UI 行、§成功（中間）

**7.** Nit — DIS-0001 §問題 > 質問 1 判断 a

**8.** Nit — DIS-0001 §関係者（エージェントホスト）
