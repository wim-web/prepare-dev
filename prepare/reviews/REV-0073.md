## 言い直し

### この文書が提案していること
prepare-dev の本体（記録を書くデーモン、CLI、検証プラグイン）を Go で作り直す。React の判断画面のビルドと skills を埋め込み、OS とアーキテクチャごとに実行ファイル一つで配る。エージェントは skills に従って CLI だけを使い（MCP の入口は無い）、人は判断画面からだけ回答する。

今回の変更は次の三つ。
- 検証プラグインの書き方（guidance）を、CLI の専用コマンドから prepare-verify の skill の references/ に移した。init で対象プロジェクトに写る。
- このリポジトリの docs/ にあった引き継ぎ・確認の記録・具体化案を、runtime を通した REC-*・PRO-* として prepare/ に移した。
- skills に「人が確かめたことは REC に書き、工程の記録を runtime の外に書かない」規則を足した。

DIS-0001・DES-0002・DES-0003 は、そこに至る問題の整理と前の設計として残る。REQ-0009・REQ-0010・SPEC-0003・SPEC-0004 は、判断画面、配布物、証拠の追跡の受入条件を決める。

### この文書によると既存の仕組みはどう動くか
- CLI は root の daemon.json に書かれた URL の /api/identity でデーモンの version と build を自分と比べる。同じなら接続し、違えば相手と止め方を示して終わる。誰も lease を持っていなければ、同じ実行ファイルの serve を端末から切り離して起動する。
- デーモンは .prepare-dev/lease の flock で書き手を一つにする。操作の前に、lease とジャーナルが開いたときのものかを確かめる。記録（Markdown と YAML）、質問と RUN（JSON）、ジャーナル（JSON Lines）を rev と sha256 で版として扱う。
- RUN が現在の版の証拠になるのは、入力ファイルの sha256、ディレクトリの一覧、仕様と要求の版、プラグインの版がすべて今と一致する間だけ。status と trace がそれを判定する。
- init は skills を .agents/skills と .claude/skills に写し、digest を skills.json に残す。次の init では、編集されていない skill だけを置き換える。
- 回答の API は同じ origin のブラウザの要求だけを受け付け、CLI に回答の操作は無い。
