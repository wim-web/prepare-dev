## 言い直し

### この文書が提案していること
prepare-dev の本体（記録を書くデーモン、CLI、検証プラグイン）を Go で書き直す。React の判断画面のビルドと skills を埋め込んだ、OS とアーキテクチャごとの実行ファイル一つで配る。MCP の入口は無く、エージェントは skills に従って CLI を使い、回答は人が判断画面からだけ行う（DES-0004、DES-0002、REQ-0009・0010、SPEC-0004）。
今回の版では、工程の外で残すものを記録の種類 record（確認記録、貼り付けた引き継ぎの原文）と proposal（工程の外で作った案）にする規則を、skills を通してすべての対象プロジェクトに求める。確認記録は、確かめた SPEC・REQ・DES を自分の related_to から指す（確かめられる側の版を進めて RUN を外さないため）。確認は一回ごとに新しい確認記録にして checked に version・build・commit を書き、古くなったことは関門にせず prepare-verify の報告で示す。
あわせて次の変更をする。
- 検証プラグインごとの主張の書き方（guidance）を、版の見出しつきで prepare-verify の references/ に移し、`prepare-dev guidance` を無くす。開発版は 0.3.0-dev にし、更新は stop、実行ファイルの入れ替え、init の実行し直しで行う。
- status が、init の入れた skills のうち古いもの・無いもの・編集されたものを示す。
- プラグインが宣言した設定の項目と型に合わない設定を、RUN の番号を取る前に拒む（SPEC-0003 V5）。
- trace は一回の中で、RUN ごとの判定を使い回す。

### この文書によると既存の仕組みはどう動くか
CLI は root の daemon.json と /api/identity を見て、version と build が同じデーモンにだけ接続する。いなければ、同じ実行ファイルを serve で端末から切り離して起動する。
デーモンは .prepare-dev/lease の flock で唯一の書き手になり、記録・質問・RUN・ジャーナルを TypeScript 版と同じ形式で書く。操作の前に lease とジャーナルが開いたときのままかを確かめ、マージ後の矛盾があれば何も書かずに status の problems に示す。
init は skills を .agents/skills と .claude/skills にコピーして digest を skills.json に残し、次の init では編集されていない skill だけを新しい版に置き換える。
検証はデーモンが lean4・vitest・gotest で動かす。RUN が現在の版の証拠になるのは、記録した入力・ディレクトリの一覧・主張の記録の版・プラグインの版が今と同じ間だけで、trace は links を両方向にたどる。
DIS-0001 は TypeScript 版の時点の問題の整理で、当時は tsx でソースを動かし、init が機械ごとの絶対パスで MCP の登録と skills の symlink を書いていた。範囲は DEC-0004・0006・0007 で置き換わった。

すべての節を言い直せた。ただし §工程の外の記録 の checked と build の比べ方は、prepare-dev 以外の対象プロジェクトでの意味が一つに決まらない（指摘 1）。
